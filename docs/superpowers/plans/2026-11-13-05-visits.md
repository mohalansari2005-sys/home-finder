# Plan 5 — Visit Planner

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bookmarked homes are grouped by district (neighboring districts within a 10-minute drive are merged) and turned into a timed, route-optimized visit trip. Each stop has a pre-filled Arabic WhatsApp message and a contact status. Listings are re-checked before the trip, there's a one-tap Google Maps route, and post-visit ratings feed the learner.

**Architecture:** Grouping, planning and link building live on the **server** (`homefinder/server/visits/`) because they only need HTTP calls to Google, which `GoogleClient` already does with httpx. `precheck_trip` is a worker job because it re-fetches listings from source sites. Visit photos are stored as uploaded (no Pillow on the server).

**Tech Stack:** As before. The server gets `GoogleClient` via `make_google(httpx.Client())`.

**Spec:** `docs/superpowers/specs/2026-11-13-home-finder-design.md` §3.8, §4 (`visit_trips`, `visit_stops`)

## Global Constraints

All constraints in `2026-11-13-00-overview.md`. Plans 1–4 must be complete and green. Trip dates and times are entered and shown in **Asia/Riyadh**. Fridays are allowed for visits (the workweek rule only applies to commute departure times).

## Review Focus

1. **A trip date/time in the past, or less than 15 minutes from now:** Google rejects past departure times, so routing uses `now + 15 min` as the departure. The displayed timeline still starts at the chosen time. Pinned in `test_departure_never_in_past`.
2. **A bookmarked listing without coordinates** can't join a route. It's listed under "بدون موقع" (no location) in the group view and excluded from trip creation, with a visible note. Pinned in `test_grouping_skips_no_coords`.
3. **Cancelling every stop but one** re-plans a one-stop trip without calling waypoint optimization (that needs ≥ 2 intermediates). Pinned in `test_replan_single_stop`.
4. **Seller phone formats** `0551234567`, `+966 55 123 4567`, `966551234567`, `551234567` all normalize to `966551234567`. Landlines and garbage give no WhatsApp button. Pinned in `test_whatsapp_phone_normalization`.
5. **Google returns no route** (a stop unreachable by car): the trip is still created in the requested order with ETAs left null for the affected legs, and a warning flag is shown. Pinned in `test_plan_with_missing_route`.

```python
import re
from datetime import datetime
from urllib.parse import quote, urlencode

from homefinder.textnorm import to_western_digits

AR_WEEKDAYS = ["الإثنين", "الثلاثاء", "الأربعاء", "الخميس", "الجمعة", "السبت", "الأحد"]


def normalize_sa_mobile(raw: str | None) -> str | None:
    if not raw:
        return None
    d = re.sub(r"\D", "", to_western_digits(raw))
    if d.startswith("00966"):
        d = d[2:]
    if d.startswith("9665") and len(d) == 12:
        return d
    if d.startswith("05") and len(d) == 10:
        return "966" + d[1:]
    if d.startswith("5") and len(d) == 9:
        return "966" + d
    return None


def _time_ar(dt: datetime) -> str:
    h = dt.hour % 12 or 12
    return f"{h}:{dt.minute:02d} {'صباحاً' if dt.hour < 12 else 'مساءً'}"


def whatsapp_link(phone: str | None, listing_title: str | None, eta_local: datetime | None) -> str | None:
    n = normalize_sa_mobile(phone)
    if n is None:
        return None
    msg = f"السلام عليكم، شفت إعلانكم \"{listing_title or 'العقار'}\" وحاب أزوره"
    if eta_local:
        msg += f" يوم {AR_WEEKDAYS[eta_local.weekday()]} الساعة {_time_ar(eta_local)}"
    msg += "، هل يناسبكم؟"
    return f"https://wa.me/{n}?text={quote(msg)}"


def _ll(p) -> str:
    return f"{p[0]},{p[1]}"


def google_maps_route(origin, stops) -> str:
    params = {"api": "1", "origin": _ll(origin), "destination": _ll(stops[-1]), "travelmode": "driving"}
    if len(stops) > 1:
        params["waypoints"] = "|".join(_ll(s) for s in stops[:-1])
    return "https://www.google.com/maps/dir/?" + urlencode(params, safe=",|")
```

**Interfaces:**
- `GoogleClient.optimize_route(origin, stops: list[(lat,lng)], departure: datetime) -> RouteResult | None`, where `RouteResult = {"order": list[int], "leg_minutes": list[int]}`. `order` maps visit order → index into `stops`. `leg_minutes` holds origin→1st, 1st→2nd, … , last→origin. It calls `computeRoutes` with `origin` = `destination` = origin, `intermediates` = stops, `optimizeWaypointOrder` = (len ≥ 2), `routingPreference: TRAFFIC_AWARE` and field mask `routes.optimizedIntermediateWaypointIndex,routes.legs.duration`. It returns `None` if no routes come back. Cost: `COST["route_optimized"] = 0.015`.
- `planner.departure_utc(d: date, t: time, now: datetime) -> datetime` = `max(local(d, t), now + 15 min)` in UTC
- `planner.plan_trip(s, google, *, listing_ids, d, t, origin_kind, minutes_per_visit, title=None, now=None) -> VisitTrip`: builds stops with positions, ETAs (ETA = previous ETD + leg minutes; the first ETA = local start + leg 0), ETDs (ETA + minutes_per_visit), `drive_min` and `total_drive_min`. Without google, or when google returns None: keep the given order, set ETAs to None, and add warning `"no_route"`.
- `planner.replan(s, google, trip) -> VisitTrip`: plans again over the stops whose status is not `cancelled` and not `visited`, keeping the trip and stop rows (positions and times are updated).
- **HTTP** (family auth):
  - `GET /api/visits/groups` → `{groups: [Group as dict + "listings": [ListingCard]], no_location: [ListingCard]}`
  - `POST /api/visits/trips {listing_ids (1..15), date: "YYYY-MM-DD", start_time: "HH:MM", origin_kind: home|school|work|university, minutes_per_visit: 15..120 = 30, title?}` → `TripOut`. Returns 422 if `origin_kind`'s place isn't set. Listings without coordinates are dropped, with a `"skipped_no_location": n` warning. Enqueues `precheck_trip` (`{"trip_id"}`, dedupe `precheck:<id>`), delayed until 3 h before the start, or immediately if that's already past.
  - `GET /api/visits/trips?status=planned|done|all` → `TripOut[]` (newest date first)
  - `GET /api/visits/trips/{id}` → `TripOut`
  - `PATCH /api/visits/stops/{id} {contact_status?, rating? (1..5), notes?}`:
    - `contact_status=cancelled` → replan.
    - `contact_status=visited` → `listing.family_status="visited"`.
    - `rating` → a `Reaction(kind="visit_rating", rating)`, then the same learn trigger as in Plan 4 Task 2.

  - `POST /api/visits/trips/{id}/precheck` → 202 (enqueues `precheck_trip` priority 10)
  - `PATCH /api/visits/trips/{id} {status}` → `TripOut`
  - `POST /api/visits/stops/{id}/photos` (multipart `file`, image/* ≤ 8 MB, saved to `photos_dir/visits/<stop_id>/<uuid>.<ext>`) → 204
- `TripOut = {id, title, date, start_time, origin_kind, minutes_per_visit, status, warnings, total_drive_min, maps_url, stops: [{id, position, listing: ListingCard, eta_local: "HH:MM"|null, etd_local, drive_min, contact_status, rating, notes, flags, whatsapp_url, phone, photos: [url]}]}`
